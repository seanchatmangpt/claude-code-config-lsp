v26.7.3 advances claude-code-config-lsp from a CANDIDATE LSP validator to a **production-ready configuration law enforcement and conformance oracle** for Claude Code. This release focuses on three pillars:

1. **Ecosystem Maturation** — Complete integration with wasm4pm-compat, OCEL event logging, and Chicago TDD patterns

## Strategic Context

### The Problem We Solve

Claude Code is an agentic system that modifies its own configuration law surfaces (`settings.json`, `CLAUDE.md`, `plugin.json`, hooks, agents, skills). Without real-time validation, the agent writes law changes that are not validated until runtime, often sessions later.

**The Gap**: Between configuration write and configuration use, there is no ambient witness. Malformed JSON, missing required fields, broken hook scripts, and invalid Declare constraints go silent until the agent tries to exercise them.

**Our Solution**: LSP closes this gap. The moment the agent writes a law surface, our server publishes diagnostics via `textDocument/publishDiagnostics`. Validation is synchronous with the write, not deferred.

### Market Position

- **User**: Claude Code agents (primary); humans (secondary, via Claude Code UI)
- **Distribution**: Claude Code marketplace (plugin ecosystem)
- **Adoption Model**: Ship as official plugin; integrate into Claude Code base suite
- **Competitive Advantage**: Ontology-driven architecture means schema changes propagate to hover, completion, and diagnostics without hand-editing code

## Feature Roadmap: v26.7.3

### P0: Ecosystem Maturity (REQUIRED)

These features unblock marketplace release and enable downstream integrations.

#### 1. OCEL Event Log Persistence (Complete)
- **Current State**: `OcelAccumulator` collects events in memory; events are never persisted
- **Goal**: Write OCEL 2.0 events to disk in structured log format
- **Deliverable**:
  - Implement `OcelPersister` that writes OCEL events to `~/.claude/logs/claude-code-config-lsp/ocel-*.jsonl`
  - Event types: `file_opened`, `diagnostics_published`, `conformance_scored`, `receipt_issued`
  - Include timestamps (UTC), URIs, event type, and severity counts
  - Rotate logs monthly (YYYY-MM-OCEL.jsonl)
  - Enable via feature flag `ocel-persistence` (default: disabled)
- **Success Criteria**:
  - At least 50 events recorded per typical agent session
  - Each event valid against OCEL 2.0 JSON schema
  - Log file size < 1 MB per month (average workspace)
- **Dependencies**: chrono (existing), serde_json (existing)

#### 2. Receipt Chain Foundation
- **Current State**: Conformance scores are ephemeral; no audit trail
- **Goal**: Create immutable receipt chain for each workspace snapshot
- **Deliverable**:
  - Define `Receipt` struct: workspace ID, timestamp, conformance score, diagnostic checksums, signer
  - Compute receipt hash: blake3(workspace_id + timestamp + score + checksums)
  - Issue receipt after each workspace scan via `claude-config://receipts/<receipt-hash>`
  - Validate receipt chain: each receipt references prior receipt's hash (Merkle chain)
  - Store receipts in `~/.claude/receipts/` with immutable semantics
- **Success Criteria**:
  - Receipt issued after each `textDocument/publishDiagnostics` batch
  - Chain integrity verified on startup (detect tampering)
  - Receipt available via URI query within 100ms
- **Dependencies**: blake3 (existing), existing Backend infrastructure

#### 3. Wasm4PM Constraint Integration
- **Current State**: Declare constraints defined in ontology but not linked to wasm4pm-compat
- **Goal**: Enable wasm4pm constraint verification and visualization
- **Deliverable**:
  - Wire `wasm4pm-compat` feature to constraint registry
  - Expose all Declare constraints via `claude-config://declare/model.xml` (PNML format)
  - Implement `verify_constraints()` method that checks event log against constraint set
  - Publish constraint violations as INFO-level diagnostics (non-blocking)
  - Add virtual document: `claude-config://declare/report` (summary)
- **Success Criteria**:
  - All 8+ Declare constraints from ontology exportable to PNML
  - Constraint violations detectable from OCEL log with < 50ms latency
  - No false positives in constraint checking
- **Dependencies**: wasm4pm-compat 26.6, existing event accumulator

### P1: Conformance Completeness (HIGH PRIORITY)

#### 4. Expanded Diagnostic Coverage
- **Current State**: ~15 diagnostic rules across 5 analyzers
- **Goal**: 40+ comprehensive diagnostic rules
- **Coverage By Surface**:
  - **settings.json** (8 rules): model ID validation, permission cycles, hook wiring correctness, env var syntax
  - **CLAUDE.md** (6 rules): section completeness, cross-reference validity, hook event name validation
  - **plugin.json** (8 rules): LSP server command validation, skill paths exist, dependency resolution
  - **marketplace.json** (6 rules): duplicate plugin names, URL reachability, version schema
  - **Frontmatter** (7 rules): required fields per file type, enum validation, array size constraints
  - **Hook Scripts** (5 rules): syntax validation, shebang presence, exit code expectations
- **Deliverable**: Add 25+ `DiagnosticRule` individuals to ontology; run `ggen sync` to regenerate analyzers
- **Success Criteria**:
  - All rules testable (test case per rule)
  - Rules discoverable via `/code-review` and workspace conformance query
  - No rule conflicts (no contradictory constraints)

#### 5. Cross-File Reference Validation
- **Current State**: Single-file analysis only
- **Goal**: Detect dangling references across config surfaces
- **Deliverable**:
  - CLAUDE.md "See Also" links: verify target files exist
  - plugin.json skill/agent paths: verify files are reachable
  - settings.json hook wiring: cross-check against hooks/*.sh files
  - Implement `Backend::scan_workspace_references()` to build symbol table
  - Issue CCC-REF-001..005 diagnostics for broken references
- **Success Criteria**:
  - Detects missing files within same scan pass
  - Handles workspace-relative and absolute paths
  - < 100ms latency for 50-file workspace

#### 6. Conformance Scoring Refinement
- **Current State**: Conformance score is (100 - 10*errors - 3*warnings); no weighting
- **Goal**: Nuanced scoring that reflects severity and category
- **Deliverable**:
  - Per-category weights: critical (settings perms) = 15pts, important (schema) = 5pts, minor (style) = 1pt
  - Distinguish workspace score (global + all projects) vs. project score (local scope)
  - Implement `ConformanceVector` (Declare-inspired): maps (surface_type, severity) → impact
  - Publish conformance vector via `claude-config://health` (JSON)
  - Add conformance trend tracking (over time)
- **Success Criteria**:
  - v26.6 workspace that scores 85 now scores 80–90 (weighted model gives finer granularity)
  - Conformance queries include time-series data (past 7 days)

**Mitigation**: Make OCEL persistence optional (feature flag); default to off

### Risk: Wasm4PM constraint checking times out on large workspaces
**Mitigation**: Implement incremental constraint verification (only new/changed events); cache results

**Mitigation**: Provide migration guide; score both v26.6 and v26.7+ models for comparison
