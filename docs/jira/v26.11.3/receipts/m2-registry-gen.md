## Root cause

ggen 26.10.11's sync pipeline is ontology→SPARQL→Tera only. The gen.toml rule's `input = "lsp-max.toml"`
refers to a retired capability. The committed registry_init.rs (101 lines, rustfmt-ed, knows
`ChildTier::DiagnosticsOnly` and all four child servers) was produced by an older pipeline shape and
has since been hand-evolved (or generated by a since-changed template — the current
`registry_init.tera` emits only Primary/Secondary tiers and non-rustfmt style; it does NOT match the
committed file even given data).

## Additional drift: template ≠ committed output

`registry_init.tera` emits `ChildTier::Primary|Secondary` only and 1-line register calls; the
committed file uses all three tiers incl. `DiagnosticsOnly` and rustfmt style. Even with a working
data path, byte-identical regeneration requires BOTH ontology individuals for the four servers AND a
template rewrite (or post-render rustfmt hook).
